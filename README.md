# 安全质量管理模块 · 研发演示站

把演示原型和需求文档发布到 GitHub Pages，得到一个**固定不变的访问地址**，以后更新只需双击 `发布更新.bat`，不用再逐个给研发发文件。

---

## 一、地址规则

| 地址 | 用途 |
| --- | --- |
| `https://<账号>.github.io/<仓库>/` | 站点首页：最新版本、更新说明、历史版本、需求文档下载。**发给研发就用这个。** |
| `https://<账号>.github.io/<仓库>/latest.html` | 直接打开最新版演示，适合收藏/加书签 |
| `https://<账号>.github.io/<仓库>/versions/<日期>-v<版本>/index.html` | 某个历史版本的固定快照，用于回溯 |

地址在仓库创建后就固定了，永远不变。

## 二、目录结构

```
demo-site/                    ← git 仓库根目录
├─ index.html                 ← 首页（脚本自动生成，不要手改）
├─ latest.html                ← 最新版演示（脚本自动覆盖）
├─ versions/
│   └─ 2026-09-17-v1.6/
│       ├─ index.html         ← 该版本演示快照
│       ├─ 需求说明书-V1.6.docx
│       └─ meta.json          ← 版本号、日期、更新说明
├─ 首次配置.bat                ← 一次性配置（连接 GitHub 仓库，双击运行）
├─ setup.ps1                  ← 上者调用的脚本（ASCII 名，勿改中文名）
├─ 发布更新.bat                ← 日常发布（双击运行）
├─ publish.ps1                ← 上者调用的脚本（ASCII 名，勿改中文名）
├─ 操作步骤.md                 ← 首次发布的完整操作指引
└─ .nojekyll                  ← 让 GitHub Pages 原样输出，不做 Jekyll 处理
```

## 三、日常更新（配置完成后）

1. 在工作区更新 `0917优化项.html`（和/或新的需求文档）
2. 回到 `demo-site`，双击 **`发布更新.bat`**
3. 填一句更新说明，等它推送完成
4. 等约 30 秒刷新 `https://<账号>.github.io/<仓库>/`

脚本会自动完成：按日期+文档版本号归档快照 → 覆盖 `latest.html` → 重建首页版本列表 → 提交并推送。**版本号从演示文件里内嵌的 `data-prd-version` 自动读取**，不用手填。

> 归档规则：目录名是 `versions/<日期>-v<文档版本>`。同一天、同一个文档版本重复发布会**覆盖该版本快照**（不产生重复目录），历史仍然完整保留在 git 提交记录里；文档版本号升了就自动生成新目录。所以想让版本列表干净，改完内容记得同步升 `data-prd-version`。

命令行方式：

```powershell
.\publish.ps1 -Note "检查类型扩展为四类"
.\publish.ps1 -Source ..\其他演示.html -Docx ..\其他需求.docx
.\publish.ps1 -RenderOnly      # 只重建首页，不发布
.\publish.ps1 -NoPush          # 提交但不推送
```

## 四、首次使用

见 `操作步骤.md`。顺序是：在 GitHub 创建仓库 → 生成令牌 → 运行 `首次配置.bat` → 运行 `发布更新.bat` 推送 → **最后**才去开启 Pages。

> ⚠️ Pages 的 Branch 下拉只列出仓库里**已存在**的分支。空仓库没有任何分支，那时下拉是空的、选不了 `main`，所以必须**先推送一次再开 Pages**。

## 五、注意

- 演示文件是**完全自包含的单文件**（无外部 JS/CSS/图片依赖），所以不需要任何构建步骤，直接托管即可。
- 本机 git 的 `schannel` TLS 后端握手会失败，脚本已统一使用 `openssl` 后端（`git config --local http.sslBackend openssl`），不要改回默认值。
- 仓库是**公开**的，任何人拿到地址都能访问，内容也会被搜索引擎收录。演示文件里含项目名称、参建单位名称等信息，如需收紧请看 `操作步骤.md` 最后的“合规提醒”。
